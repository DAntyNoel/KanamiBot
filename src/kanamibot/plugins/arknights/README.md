# 明日方舟查询

使用独立 Amiya MCP 后端，NoneBot / NapCat 只负责群聊命令和发送结果。不要求绑定森空岛。

## 命令

前缀为 `#粥`、`#方舟`、`#ark`（英文不区分大小写），后接空白。
查询对象在前，分项在后：

| 示例 | 功能 |
| --- | --- |
| `#粥 银灰` | 干员资料卡 |
| `#粥 银灰 技能` | 与 `#粥 银灰` 相同的干员资料大图 |
| `#粥 德克萨斯 异格 技能` | 自动查询缄默德克萨斯的资料大图 |
| `#粥 陈 异格` | 陈有多个异格，展示候选，由本人选择 |
| `#粥 国度 敌人` | 限定敌人类型，避免与同名干员混淆 |
| `#粥 银灰 天赋` | 也支持特性、属性、档案、基建等分项 |
| `#粥 银灰 模组` | 也支持材料、专精、精英化、皮肤、召唤物 |
| `#粥 固源岩 材料` | 材料详情；查询干员名时为养成材料 |
| `#粥 1-7 关卡` | 关卡卡片 |
| `#粥 晕眩 术语` | 术语解释 |
| `#粥 卫 银灰` | 当期卫戍棋子资料；未参与当期则明确提示 |
| `#粥 卫 炎 盟约` | 当期盟约效果和棋子 |
| `#粥 卫 <名称> 策略` | 当期策略技能和解锁条件 |
| `#卫 炎 盟约` | `#卫` 是 `#粥 卫` 的快捷前缀，棋子与策略查询同样适用 |
| `#卫 boss` | 本期全部关底领袖头像，每行 5 个，显示固定编号与完整名字 |
| `#卫 boss 1` | 指定编号的普通版本，展示 PRTS 原文 |
| `#卫 boss 1 隐秘` | 指定隐秘核心版本，也接受 `（隐秘）`、`隐秘核心` |
| `#粥 盐酸 餐食` | PRTS 生息演算资料检索、正文摘录和原文链接 |
| `#粥 <关键词> wiki` | PRTS 通用页面检索 |
| `#粥 选择 2` | 选择刚才的第 2 个候选，5 分钟内有效 |
| `#粥 帮助` | 命令说明 |

`卫`、`卫戍`、`卫戍协议` 等价；`盐酸`、`演算`、`生息演算` 等价。
玩法词也可以放在对象之后，例如 `#粥 银灰 卫`。

Boss 查询也接受 `#粥 卫 boss`、`#方舟 卫 boss`、`#ark 卫 boss`。
名单和本期数值来自 PRTS《卫戍协议·规程/PRTS盟约记录》，现有 10 个编号按该期顺序
固定，新增条目追加在末尾。未列出独立隐秘版本的领袖会明确提示，不能借用普通版数值。
能力、技能及通用属性直接取敌人条目原文，保留 PRTS 默认修正文案，去除网页操作控件、
隐藏术语浮层和重复版本；按请求选择普通／隐秘资料，不生成机制总结或重新计算数值。
本期卫戍数值与敌人条目的“通常数据”分栏标明，后者不冒充卫戍关内面板。
新敌人尚未补齐的隐秘详细表不以普通表代替。图片不展示来源小字，修订链接和
CC BY-SA 3.0 署名保留在文字降级回复中。
PRTS 页面缓存 10 分钟，头像缓存 1 小时；数据或结构不可用时明确报错，渲染失败时发送
完整文字摘录和原文链接。只读取 PRTS API 与图片域名，不需要修改 Amiya 后端。

资料卡发送成功时只展示图片，不重复附带卡片中的标题或正文；搜索候选卡只额外附带
选择命令提示。卡片无法发送时自动返回文字资料，技能分项与直接查询干员使用同一张资料大图。
同名精确命中敌人和干员时，额外提示两种筛选及命令示例，例如 `#粥 塔露拉 敌人`、
`#粥 塔露拉 干员`；指定其中一种后仍可看到切换提示。

异格根据本地游戏数据的关联组解析，支持绰号后加“异格”；已经使用异格名称或绰号时
保留该形态。没有已知关系时不会猜测。正式名称和本地绰号精确命中优先，模糊结果
即使只有一个也会按搜索结果处理；多候选选择绑定机器人、群/私聊、用户，不会串群。

肉鸽按需求仅考虑全体玩家统计结果。目前未确认 PRTS 提供可用的这类统计数据来源，
所以不接入个人结算或肉鸽小游戏，也不提供肉鸽藏品查询。

## 本地绰号

```text
#粥 绰号 缄默德克萨斯 异德
#粥 绰号 易得 删除
#粥 绰号 列表
```

初始表和来源见 [本地资料](../../arknights/assets/README.md)。
自定义记录保存于 `data/arknights/nicknames.json`（Git 忽略）；删除种子绰号会保存
删除标记，重启和后端每小时同步均不会使同名绰号恢复。添加同名绰号可重新启用。
列表按阵营组织为合并转发聊天记录，每个阵营独立节点；较长阵营拆分续页。

默认所有群成员可以维护，全局共享。不同干员不能占用同一个绰号；正式干员名、命令词
不能被覆盖。需要限制维护权限时设置 `ARKNIGHTS_NICKNAME_ADMIN_ONLY=true`，群内仅
管理员/群主/超管可修改，私聊仅超管。查询和列表仍对普通成员开放。

## 后端部署

在仓库根目录运行：

```powershell
docker compose -p kanamibot-arknights -f services/amiya-mcp.compose.yml up -d
```

使用固定版本和镜像摘要的 Amiya MCP 1.1.2，独立容器 `kanamibot-amiya-mcp`，
只绑定 `127.0.0.1:19090`；资源挂载在 `data/amiya_mcp/`，建议至少预留 20 GiB。
首次启动先下载并校验游戏资源，资源就绪后才启动接口；Windows 挂载目录的文件解压
和权限归一可能较慢。检查：

```powershell
docker logs --tail 50 kanamibot-amiya-mcp
Invoke-RestMethod http://127.0.0.1:19090/rest/status
```

环境变量：

```dotenv
ARKNIGHTS_ENABLED=true
ARKNIGHTS_MCP_URL=http://127.0.0.1:19090/mcp
ARKNIGHTS_TIMEOUT=90
ARKNIGHTS_NICKNAME_ADMIN_ONLY=false
ARKNIGHTS_BROWSER_CHANNEL=chrome
```

后端换地址时，同时修改 `services/amiya-mcp.json` 的 `BaseUrl`，使返回图片 URL 与
`ARKNIGHTS_MCP_URL` 具有相同协议、主机和端口；图片由 Bot 下载后上传至 QQ。
后端不可用时显示错误，不影响其他插件。单次查询使用独立 MCP 会话，兼容 JSON 与 SSE
响应；结束时关闭会话，不需要给机器人引入大模型。

`/enable arknights`、`/disable arknights` 沿用本仓库的本群模块管理。
代码通过插件目录扫描加载，更新代码后需要用户自行重启/重载 NoneBot；部署后端不会
改动已运行的 QQ Bot、NapCat 或其他容器。

Boss 卡片在 Bot 本地使用 Playwright 渲染，外观沿用现有 `#粥` 敌人卡的深色背景、
领袖红色标识、白底分区标题与橙色强调。Windows 默认使用已安装的 Chrome，其他系统
默认使用 Playwright Chromium；可用 `ARKNIGHTS_BROWSER_CHANNEL=msedge` 切换浏览器。
